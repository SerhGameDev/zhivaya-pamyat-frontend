# Живая память — локальный прототип

Проект расположен на рабочем столе в `zhivaya-pamyat-frontend`.

## Быстрый запуск

Дважды нажмите `start.cmd`. Оставьте окно открытым. Перейдите на http://127.0.0.1:5173. Админ-панель: http://127.0.0.1:5173/#admin. Пароль генерируется при каждом запуске и указан в окне сервера. При перезапуске войдите повторно. Для постоянного пароля задайте переменную окружения ADMIN_PASSWORD перед запуском.

Готовая сборка уже находится в dist. После изменения исходников её нужно пересобрать.

## Разработка

Требуется Node.js 22.12+ и pnpm либо npm. Установка: `pnpm install` или `npm install`. Разработка: `pnpm dev` или `npm run dev`. Сборка: `pnpm build` или `npm run build`. Запуск сборки: `node server.mjs --production`. В этой установке Node также доступен в каталоге runtime Codex, который использует start.cmd.

## Просмотр на телефоне

Компьютер и телефон должны быть в одной доступной локальной сети. Откройте на телефоне `http://IPv4-компьютера:5173`; адреса печатает сервер. Во время подготовки Ethernet-адрес компьютера: `10.201.164.121`, то есть http://10.201.164.121:5173. Адрес может измениться. Адрес виртуального VPN-адаптера использовать не следует. Если страница не открывается, проверьте изоляцию клиентов Wi-Fi и доступ Node к входящим подключениям в частной сети Windows. Настройки брандмауэра автоматически не меняются. Компьютер должен оставаться включённым. Фактическая доступность с телефона ещё не проверена.

## Содержание и админка

- Изменение вводного текста, описаний, статуса и расположения памятников.
- Добавление нескольких памятников, переключение между ними в блоке «О проекте».
- Добавление биографий, отдельные страницы историй, связь с памятником.
- Редактор меток: нажмите на изображение для новой точки, задайте название, описание и координаты в процентах.
- Кнопка «Сохранить изменения» пишет данные на диск, а не только в браузер. Другие устройства увидят их после обновления страницы.
- Импорт JSON подготавливает данные к сохранению, экспорт скачивает текущий черновик.
- Изображения пока добавляются вручную в public с указанием пути `/имя.png`. Для production затем пересоберите проект. Можно также указать HTTPS URL. Загрузка медиа через админку пока не реализована.

`data/content.json` — основное хранилище. `data/content.json.bak` — предыдущая версия перед последним сохранением. Запись атомарная, поля проверяются сервером, revision предотвращает потерю параллельных изменений. После конфликта сначала экспортируйте свой черновик, затем обновите страницу. JSON не следует менять вручную одновременно с работой редактора.

## Структура и переход на ASP.NET Core

`src/api.ts` содержит типы данных и единую точку работы с API. `src/main.tsx` — публичные страницы и редактор. `src/style.css` — адаптивное оформление. `server.mjs` — временный Node HTTP API и раздача фронтенда. `data/content.json` — данные, `public` — исходные изображения.

Контракт: GET `/api/content` возвращает Content; POST `/api/login` принимает `{password}` и возвращает `{token}`; PUT `/api/content` принимает Content с текущей revision и Bearer-токеном, возвращает сохранённый Content с новой revision. Ошибки имеют формат `{error}`. Основные ответы: 400 — неверные данные, 401 — вход, 409 — конфликт.

ASP.NET Core может реализовать эти же маршруты без переписывания экранов. Для другого адреса API задайте `VITE_API_BASE_URL` при сборке и настройте CORS на сервере. Следующий этап: полноценная авторизация и роли, база данных, загрузка медиа, черновики и публикация, аудит изменений. Текущая авторизация с единым паролем и HTTP предназначена для доверенной локальной сети. Для публикации в интернете нужны HTTPS и полноценная серверная защита.

## Решения прототипа и ограничения

Светлые текстовые разделы, тёмная сцена памятника и бронзовые акценты. На узком экране секции идут в одну колонку, описание метки открывается снизу. У деталей есть текстовые кнопки, поэтому не обязательно попадать в точку. Шрифты Google Fonts необязательны: без интернета используются системные.

Имена и биографии не выдуманы. Описания шлема и противогаза явно демонстрационные. Статус памятника — концепция на обсуждении. На следующем этапе стоит проверить на реальных смартфонах размер точек, длину биографий, удобство редактирования координат и выбор нескольких памятников. Сейчас нет фото в биографиях, поиска, карты, загрузчика файлов и отдельного статуса публикации записей.

## Ракурсы и изображения

На первом экране теперь единая зелёная сцена с двумя ракурсами. Кнопки под скульптурой переключают изображения с анимацией. Для пользователей с настройкой уменьшения движения анимация отключена. Светящиеся точки имеют небольшую видимую часть и область нажатия 44×44 пикселя.

В админке в разделе памятника можно добавить ракурс, изменить его название, загрузить PNG/JPEG/WebP до 8 МБ и поставить собственные точки на каждый снимок. После загрузки и редактирования нажмите «Сохранить изменения». Изображения хранятся в public/uploads и доступны сразу без пересборки. Удаление ракурса убирает его из JSON, файлы остаются на диске для восстановления. Экспорт JSON не включает изображения: резервируйте также папку public.

Модель Monument дополнена необязательным массивом views: [{id,label,image,hotspots}]. Старые записи с image/hotspots продолжают работать. POST /api/images с Bearer-токеном принимает {data: base64}, возвращает {url}. Формат определяется по сигнатуре файла. GET /uploads/имя раздаёт сохранённые изображения. При переносе на ASP.NET добавьте аналогичный загрузчик и хранилище медиа.

## Новые возможности редактора
Вход в локальную админку без пароля. API записи и загрузки также открыт для устройств локальной сети; не публикуйте этот прототип в интернете. Для ASP.NET следует вернуть серверную авторизацию.
Памятник поддерживает свайпы. Параметры Monument: scale (60–150 процентов), pointSize (4–20 пикселей), showLabels (подписи с линиями). У Hotspot есть photos: string[]: загрузите несколько фотографий или задайте пути по одной строке. В описании сначала показывается карусель фотографий, затем текст. Фото можно удалять и переставлять редактированием списка путей. Компоненты Gallery и PhotoCarousel отделены от API и модели данных в src/api.ts.
